# zv-drama-simple

把小说或故事梗概制作成 AI 短剧视频的独立技能。当前版本：**1.01**。

当前开发分支：`codex/remove-image-review`。本分支取消 Agent 图片验收与自动重做，保留所有图片步骤的 HTML 展示和用户聊天确认；尚未据此更新全局安装版。

技能自行完成改编、人物与美术设定、剧本、站位、分镜、素材展示和交付流程，不依赖原有小说制作技能。图像与视频生成使用当前环境实际可用的工具或技能。

执行规则见 [SKILL.md](SKILL.md)。本文件介绍当前能力并记录重要修改，不代替执行规则、数据 schema 或用户确认。

## 使用与环境

安装后，在支持技能的 Agent 中指定使用 `zv-drama-simple`，提供小说文件或故事梗概，以及已有的制作要求。例如：

> 使用 zv-drama-simple 将这份小说改编成短剧，先制作第一集，每一步展示后由我确认。

- Python 3.10+；核心脚本使用标准库，无需安装 pip/npm 依赖。
- 视频检查与合成需要 `ffmpeg`、`ffprobe`。
- 需要宿主提供实际生图、生视频能力；缺失时明确提示，不用占位图或提示词冒充成品。
- 媒体上传地址、鉴权及模型能力使用当前用户环境的配置，不将个人凭据写入项目或技能。

## Agent 运行前要准备什么

安装技能只是提供流程与脚本，不会自动安装生图、生视频模型，也不会自动配置账号。Agent 应先检查实际可用能力、文件权限和工具限制，再开始对应制作阶段；缺失项明确告知用户，并继续完成不依赖该能力的已授权工作。

### 基础环境与输入（开始前必需）

| 准备项 | Agent 要检查什么 |
| --- | --- |
| 完整技能目录 | 能读取 `SKILL.md`、`references/`、`schemas/`、`templates/` 和 `scripts/`，不是只有一份技能说明。 |
| 文件与命令能力 | 能读用户授权的小说文件、运行 Python 和本地命令、创建独立项目目录，写入 JSON、媒体和审核页；项目目录与技能安装目录分开。 |
| Python 运行环境 | `python3 --version` 为 3.10+。当前脚本使用 `fcntl` 文件锁，原生适用于 macOS/Linux；Windows 应使用 WSL 等兼容环境，不能假定原生 Windows 可直接运行。 |
| 小说与制作要求 | 取得完整小说或获准扩写的梗概，整理集数、单集时长、画幅、风格、改编范围和声音方案；已有要求不重复询问，缺失的关键参数集中询问。 |
| 正文提取能力 | 按输入格式检查转换工具。文本型 PDF 需要 `pdftotext`；部分其他文档格式需要 `pandoc` 或可用文档读取工具；扫描件、图片需要 OCR。转换后必须核对完整性，不能只改扩展名。 |
| 展示与持续保存 | 能向用户提供本地 `reports/index.html` 和本步审核页的可访问入口，并持久保存项目文件及 `workflow.json`，以便中断后恢复；无需启动 Web 服务。 |

### 图像、视频与声音（进入相关阶段前必需）

| 能力 | 最低准备要求 |
| --- | --- |
| 实际生图 | 已连接可调用的生图工具，能够保存真实图片；分镜关键帧生成必须支持实际输入角色、场景和俯视图等参考图片。先核实输入数量、格式、尺寸和并发限制，可并发时最多 5 个，工具上限更低时服从工具上限。 |
| 参考图读取与展示 | Agent 能读取已有参考图以准备生成输入、布局和站位，并向用户展示真实生成图片；不需要逐图质量验收、评分或候选选优能力。 |
| 实际生视频 | 发现并验证当前可用的视频工具或技能及其底层连接、认证。参考图模式至少可同时输入关键帧与俯视图；首尾帧模式必须支持首帧、尾帧加额外俯视图。记录真实时长、图片数量、画幅、音频和音色参考限制，不预设供应商或模型。 |
| 异步任务与下载 | 若服务异步生成，应能提交、查询状态、获取结果并保存真实任务 ID；超时先查任务，不盲目重复提交。结果需要落到项目可读取的真实媒体文件。 |
| 媒体处理 | `ffmpeg -version`、`ffprobe -version` 可运行，用于检查视频、提取音色、处理音轨、剪辑和合成。 |
| 看片与试听 | 能播放或分析实际视频与音轨，检查对白、口型、人物、背景和镜头连续性；抽帧不能代替试听，`ffprobe` 也不能代替内容验收。 |
| 素材上传与音色 URL | 配置当前用户授权的上传工具或服务，能够把需要 URL 的图片和音色样本上传，并返回生成服务可访问的 URL；有效期需覆盖生成与后续复用。角色首次说话后要保存并上传真实音色样本，后续在视频工具支持时携带。 |
| 账号与执行授权 | 核实所选服务的登录、凭据、可用额度以及用户授权范围。复用已有有效配置和授权，不重复索要密钥；不输出密钥，不写入项目、README 或日志，也不把一个服务的授权自动套给另一个服务。 |

只安装了“视频生成技能”但未连接其实际工具、未完成认证，仍不算具备生视频能力。缺少满足参考图要求的能力时，应明确提示用户需要接入什么能力，不能静默改为纯文生视频或省略俯视图。

### 按制作方案准备的可选能力

- **外部配音**：选择外部声音方案时，需要已可用的 TTS 或录音能力；要求严格口型匹配时，还需要实际口型修正能力。仅混音不能保证口型正确。
- **语音转写与对齐**：需要自动生成精确字幕时，可准备可用的转写/对齐工具；也可逐句试听定位。字幕依据最终音轨，不能直接套用剧本估时。
- **特殊输入读取**：网页、多卷小说、加密或复杂文档需要对应的获取、解密授权或读取能力，先解决完整正文来源，再进入改编。

### 建议的启动检查顺序

1. 读取技能说明，确认输入、项目目录和已有制作要求；检查 Python、文件读写权限及所需正文提取工具。
2. 初始化项目，转换并核对 `source/novel.md`；检查 `ffmpeg`、`ffprobe` 和实际看图、看片、试听能力。
3. 盘点可用生图、生视频及上传工具，核实认证与授权；把视频能力依据和限制登记到 `brief.videoGeneration`，尚不可用时如实登记缺项。
4. 展示第 1 步制作要求等待聊天确认；进入分镜和真正提交生成任务前，再核实相关能力和素材 URL 是否仍可用。

## 当前制作流程

| 步骤 | 内容 | 主要数据 |
| --- | --- | --- |
| 1 | 制作要求与小说规范化 | `brief.json`、`source/novel.md` |
| 2 | 改编大纲 | `outline.json` |
| 3 | 角色设定 | `characters.json` |
| 4 | 场景与道具设定 | `art.json` |
| 5 | 分集剧本 | `script.json` |
| 6 | 角色定妆 | `anchors.json`、角色设定图 |
| 7 | 制作参考图与场景俯视图 | `assets.json`、`floorplans.json`、图片 |
| 8 | 场次站位 | `staging.json` |
| 9 | 分镜方案 | `storyboard.json` |
| 10 | 分镜图 | `frames.json`、关键帧或首尾帧 |
| 11 | 视频片段与角色音色 | `clips.json`、`voices.json`、视频和音频 |
| 12 | 每集成片 | `edit.json`、成片和必要字幕 |

图片产出只做文件、格式、引用和布局数据等基础校验，视频仍需实际看片与试听；各步以只读 HTML 展示，由用户在聊天中确认。项目首页是 `reports/index.html`；`workflow.json` 保存步骤状态、版本和确认记录。上游内容变化后，受影响的确认会失效，需要重新审核。

从第 6 步开始，可选择仅第一集或所有集，**默认仅第一集 E01**。前五步的文字规划与实际生成素材的范围分开管理。

## 重要修改记录

当前版本号保持 **1.01**。以下按主题归纳已落地的重要修改；未单独发布新版本的调整也记在 1.01 下，不为早期修改补造日期或版本号。

### 2026-11-21 · 移除 Agent 图片审核（开发分支）

- 覆盖角色设定图、派生状态图、道具图、场景图、俯视图、分镜关键帧与首尾帧：取消逐图视觉验收、组内/邻接冲突审核、评分选优及质量问题触发的自动重做。
- 图片 `qc` 不再必填；旧 QC 对象兼容存档，但不读取、不展示、不要求保留旧候选文件。旧 `image_review.py` 命令返回停用说明，不再选择候选或发出重做指令。
- HTML 保留真实图片、提示词、参考关系、实体分组与布局信息，移除图片验收结论和候选检查栏。
- 图片生成后仍需用户确认，只有用户要求修改时才修图并重新展示；视频与成片审片、小说完整性核对、文本方案检查、文件与数据约束均保留。
- 生成前的参考图输入、角色设定板版式、每场景唯一俯视图、最多 5 个并发请求不变。生成失败的服务重试不等于自动质量重做，仍须核对任务状态以避免重复提交。
- 旧项目无需补造图片 QC，原对象可以保留。重新提交受影响步骤时仍需真实用户确认，不自动批准。版本暂保持 1.01，此开发分支尚未覆盖全局安装版。

以下为历史修改记录；与本分支冲突的图片审核与自动重做规则已由上述变更取消。

### 2026-11-19 · 1.01 后续调整

- **俯视图并入第 7 步**：取消独立的第 8 步俯视图确认，整体由 13 步调整为 12 步。每个新场景的首张场景图完成验收选图后，立即制作并校验该场景唯一的俯视图，与场景图一起展示确认。
- **同场景复用唯一俯视图**：昼夜、光照、天气等状态不重复生俯视图；新增状态与已有布局交叉检查，必要时更新验收记录。真正改变建筑布局须先修订设定或明确登记新场景，不能给同一场景叠加多张布局。
- **合并审核与追踪**：保留独立 `floorplans.json`，但纳入 `assets` 的校验、版本指纹及历史归档；俯视图修改会使第 7 步及相关下游确认失效。旧项目的独立俯视图确认记录保留为历史，不自动迁移为新流程已确认。
- **生图最多并发 5 个**：工具支持并发时，独立且依赖已就绪的任务可并发；实际遵守工具更低的上限。异步未结束任务也占名额，同一张图的重做依次执行，共享 JSON 串行归档。
- **卡片展开不撑开网格**：保留固定卡片占位，完整内容浮层展开，长内容在卡片内滚动，避免同排其他卡片下方出现大片空白；标题使用重点色。

### 1.01 · 重要能力与规则累计

| 主题 | 已落地的修改 |
| --- | --- |
| 独立技能 | 创作规则、JSON schema、HTML 模板和脚本自包含；不依赖原大纲、角色、美术、剧本或分镜技能。 |
| 小说输入 | 任意格式输入先转换并核对为 UTF-8 `source/novel.md`；后续小说参考只读这份 MD，原文件仅归档。 |
| 图片质量 | 每张图按描述实际检查并记录依据。首次生成后最多重做 3 次，总候选最多 4 张；通过即停止，耗尽后选最合适的一张，明确残留问题，不能假称通过。 |
| 同实体状态 | 同一人物、道具、场景的不同状态按实体分组；新状态对照组内图片检查，相关旧验收随素材变化重新核对，保留候选和重做计数。 |
| 相邻场景 | 对物理临近或内外连通的场景，检查位置、方向、相对大小与连接结构是否冲突，未知关系不擅自补成事实。 |
| 参考图输入 | 生图工具支持图片输入时实际传入相关依赖图，并说明各图的位置、尺度和方向约束，不能只填写引用 ID。 |
| 空间连续性 | 俯视图核对布局、门窗、家具、方向、通道和未知区域；分镜关键帧与视频请求都携带对应俯视图，用于约束机位移动与背景变化。 |
| 角色设定图 | 左侧清晰正面大头/半身像，右侧正、侧、背全身三视图，底部服装、手、鞋细节；去掉头发局部图。除正面大图外，其他视图出现的头部打马赛克，以正面大图作为身份参考。 |
| 角色音色 | 从视频模型首次生成的角色说话视频中提取音色样本，保存文件并上传取得 URL；后续该角色的视频请求在工具允许时复用，不能伪称不支持的模型已携带音色。 |
| 分镜知识库 | 内置《AI 短剧分镜 Agent 知识库 V1.0》，分镜时尽量遵循，并按 P0/P1/P2 复核；不为套用规则擅改已确认剧情。 |
| 视频生成方式 | 分段选择 `ref2v` 或首尾帧并简述理由；`ref2v` 说明需要生成的分镜帧数量。首尾帧方式须确认工具能同时接收首尾帧和俯视图。 |
| 视频能力发现 | 不固定指定 Wan3；从当前工具、技能中查找可用视频生成能力，找不到则提示用户需要补充能力。旧 Wan3 适配器仅保留兼容用途。 |
| HTML 审核 | 统一首页组织步骤；剧本页头解释编号缩写；分镜图按“集 → 小段 → 镜头”展示；HTML 只展示，确认在聊天中进行。 |
| 连续执行 | 无需用户确认的工作继续执行；因待确认而结束回复时，明确说明本次确认内容、残留问题、审核入口，以及确认后的下一步。 |
| 发布整理 | 排除本地测试、演示产物、私人配置及开发辅助文件，使用者所需的运行脚本、模板、schema 和知识库随技能提供。 |

## 升级旧项目

旧的 13 步项目需使用当前脚本刷新审核页，并重新提交第 7 步 `assets`。确认时同时检查场景图和 `floorplans.json`，随后复核受影响的站位、分镜及视频数据。不要直接沿用旧的独立俯视图确认或手工将步骤标为已通过。

新增场景状态只意味着复用原俯视图并展示给用户，不代表需要再生一张。若已有项目为同一场景登记多张俯视图，应先核对并确定唯一有效布局及其下游引用，不能静默删除图片或改写历史。
