# 生图时实际传入依赖图

每次生成或重做图片前，检查当前宿主生图工具是否支持图片输入、支持多少张、接受本地文件还是 URL，以及是否支持编辑/多图参考。以当前工具的真实参数为准，不套用视频模型的九图限制，也不猜测未提供的参数。支持传参考图时，应实际传入与本图相关的依赖图；只在提示词写素材 ID、文件路径或“参考上一张”不等于工具已经收到图片。

## 选取相关图片

- 人物状态/视角图：传同一角色定妆锚点，以及与目标最接近的已确认服装、姿态或剧情状态图，固定身份、体型与衣物特征。
- 道具状态图：传同一物件的基准图及相关前态图，固定形状、材质、比例和尺度参照，仅改变本次获准的状态。
- 场景状态图：传同一场景的基准图；与已有场景物理临近或连通时，传相关相邻场景图，固定共享门窗、连接方位、相对尺度及可见背景。
- 俯视图：传本场景已验收图片作为布局依据；有相邻空间时，可补充相关场景图/已确认的空间依据，说明只用于对齐边界、方向和尺度。
- 分镜图/首尾帧：传当前镜头所需的人物、场景、道具状态图与俯视图；需要连续性时补充已确认的相邻镜头图。避免传错时间状态，比如动作前却使用破损后的道具。

只传能约束当前画面的相关图片，不把全剧图库都传进去。没有真实可用的依赖图时，不能假称已经以图为参考生成。选择仍须遵守当前制作范围及图像数据引用规则。

角色设定板的面貌来源仅为左侧清晰正面大头照；其他视图的头部已打马赛克，只参考身体、服装和姿态。提示词明确马赛克不是外貌，生成的分镜与视频不得出现马赛克；传图前核对实际文件确已处理，不能仅靠 HTML 覆盖层遮挡。

## 在提示词中明确每张图的用途

将实际输入顺序与素材 ID 对应，逐张写清：

1. **保持什么**：人物身份；门窗和家具的相对位置；共享物件的宽高比例；通行方向、空间朝向等。
2. **允许改变什么**：本次目标视角、光照、表情、服装、开合或破损等已明确状态。
3. **如何对齐**：以哪个门框、物件或人物为共同参照；观察方向是什么；哪个物件位于谁的哪一侧。区分场景方位与画面左右，不用不同视角下的像素大小直接代替物理大小。
4. **不能混入什么**：俯视图只约束布局，正常镜头不出现平面图；相邻场景图只约束连接关系，不把两个房间混成一个；人物图的背景不自动带入新场景。

示例：“输入图 1（A03）是客厅基准，输入图 2（A07）是其北侧走廊。本次生成从走廊朝南看客厅的画面。保持同一门洞的尺寸、门框轮廓和两侧地面高度；反向视角下按空间方位重新投影，不机械复制客厅图的画面左右。只改变机位，不改变门的位置或扩大走廊宽度。” 示例的事实必须由项目已有关系支持，不能直接套用。

## 输入限制与记录

- 本地文件输入受支持时使用实际本地图片；工具仅支持 URL 时按用户已授权方式上传所需素材再传 URL，不在不需要时额外上传。
- 数量超限时按本镜关键约束选取基准、最近状态、空间关系图，说明未传入哪些依赖及影响；必要时分步编辑生成，但每个正式输出目标仍遵守原有候选与最多三次重做规则。不能拆任务来绕过重做上限，也不能暗中丢掉关键依赖。
- 工具不支持传图时，明确告知并在检查说明中记录“未传参考图：工具不支持”；能在已授权范围内切换到支持传图的工具则直接使用，否则采用可用方式，不能声称实现了图像条件约束。缺少关键能力导致无法满足目标时说明具体阻塞。
- `referenceIds` / `assetIds` 继续保存项目的语义依赖，不能拿它们当实际上传凭据；不为了增加工具输入而把严格 schema 不接受的跨阶段 ID 硬塞进去。实际每次使用的素材 ID、文件、输入顺序及用途写在该候选 `attempts[].prompt` 的参考图说明中，并与真实工具调用一致；未传入项及理由写入 `qc.notes`。辅助的跨阶段参考可以在这份说明中记录，不能因此跳过它自己的来源核对。
- 先实际查看依赖图再生成。保存实际调用与返回结果，不能用计划传图清单冒充已执行输入。

分镜关键帧的场景俯视图是必传输入，不适用上述“工具不支持则采用无图方式”的降级。张数不足时先调整制作方案，不能省略俯视图；没有支持图片输入的可用工具则说明阻塞。

传入参考图只增加约束，不保证生成正确。每张候选仍执行目标描述、同组状态、相邻场景和俯视空间检查；位置、大小、方向冲突或无法判断时按原规则修正、重做和选优，最终展示残留问题并等待该步骤确认。
