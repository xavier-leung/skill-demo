# 角色音色库：从首次说话视频建立并复用

## 核心规则

人物设定里的 voiceDirection 只是初始音色方向。真正的角色音色基准来自**视频模型首次为该角色生成、经实际试听可用的说话片段**：截取该人物单独的语音，保存 WAV，上传得到 URL，按角色 ID 登记。此后人物有对白且接口/模式支持参考音频时，自动带上该音色 URL。

音色库是 clips 阶段内维护的制作资产，不额外增加一个全剧审批步骤。clips 审核页带音色播放器，也可以打开单独的 reports/voices.html；用户在聊天中试听反馈。

无对白、只出现在画面里的角色不需要硬塞音频，避免模型凭空加台词。独立配音/静音方案不向视频模型附加角色音色；该方案的声音由实际配音音轨管理。

## 首次建立音色

1. 根据 storyboard 的节拍引用定位每个人第一次说话的分段。该人物尚无音色时，先生成这个分段，不抢先批量生成他的后续对白。第一次请求使用人物初始 voiceDirection，避免多人重叠说话和强背景音乐。
2. 用正常 Wan3 collect 下载视频。返回的 voiceCaptureNeeded 会列出需要提取音色的人物；不能只下载就立即发下一段。
3. **实际播放、试听**。找出该角色自然清晰、独立完整的对白范围，尽量选可辨识声线的数秒片段；台词短时保留实际可用范围，不拉伸或循环制造长音频。
4. 确认没有其他说话人重叠、明显混响/音乐遮盖、串人声、严重失真或错台词。转写/对齐可帮助定位，但说话人身份仍需结合画面和剧本核实。背景音乐不能靠单纯裁切自动消除。
5. 以视频中**实际音色**写 description，标明音高、厚薄、质感、年龄感及口音等；不要把事先希望得到的 voiceDirection 当成实际观察。
6. 执行 capture，登记实际截取时间、对应本角色的对白节拍、试听结论。脚本只做裁切和格式统一，保留声线，不做变调、TTS 替换或伪造声音。

```bash
python3 {skill}/scripts/voices.py capture {project} C01 \
  --job 'SEG01-实际任务后缀' --start 2.1 --end 5.4 \
  --beat B02 \
  --description '实际听到的音色描述' \
  --notes '已核对该人物发声；此范围只有他一人说话，台词完整，无遮挡的背景人声或强音乐'
```

多个连续本角色台词可重复 --beat。时间必须来自实际视频，不照抄分镜预计秒数。代码拒绝无音轨、全静音、越界、过短、其他人物节拍和已经变更的来源版本；它不能仅凭波形证明是真人声或单一说话人，所以上述实际试听不能省略。

如果该人物第一段没有干净独立语音，先修复/重做该分段，或通过实际具备的人声分离能力处理并核对；本版 capture 不含人声分离器，不能把混合对话假标为单人音色，也不要改用后续随机声线偷偷覆盖首次基准。处理工具无法解决时说明具体阻塞。

## 保存、上传与恢复

- `audio/voices/C01-<来源指纹>.wav`：单声道 PCM 音色文件，长期保留。
- `voices.json`：角色 ID/姓名、实际音色描述、文件哈希、上传 URL、来源任务/视频/时间段/台词、试听记录。
- URL 使用用户配置的 upload-test 上传服务；不在 URL 中拼接凭据。

本地截取先保存，再上传。若上传失败，记录保留 status=local；恢复上传即可，不重新生成视频或反复截取：

```bash
python3 {skill}/scripts/voices.py publish {project} C01
python3 {skill}/scripts/voices.py status {project}
python3 {skill}/scripts/voices.py render {project}
```

同一角色音色一旦建立，不用后续生成结果自动覆盖。重复执行相同 capture 为幂等操作；更换来源会被拦截。若用户明确要求换声线，先保留旧库和音频、记录新指令，按新的角色音色方向重新建立，不能默默删除旧记录重来。跨批次沿用同一人物时复制对应 voices.json 和音频文件，保留来源信息，不重新抽一个随机声音。

URL 失效时 publish 可重新上传同一音频，音色内容保持不变。已准备但尚未提交的任务会因音色 URL/库变化被拦截，重新 prepare 后使用新地址；不要改一个旧任务里的 URL 继续发出。

## 后续请求自动使用

```bash
python3 {skill}/scripts/wan3.py prepare {project} SEG02
```

prepare 自动查看本段实际说话人和角色音色库。只要满足以下条件，就加入 `media` 的 `{type: "reference_audio", url: "已保存URL"}`；不会每次重新上传同一音频：

- brief 为 native 且 Wan3 audio=true。
- 当前模式支持 reference_audio（本版 ref2v）。
- 该角色已有 ready 音色，文件哈希与登记一致。

提示词明确音频属于哪个角色，只保持音色，仍说当前段台词，不复读参考音频、不把一个角色声音套给其他人。首次还没有声音的角色会标记 bootstrap；已有音色尚未上传时先阻止新请求，避免不知不觉换声。

`--reference-audio` 不再接受无角色绑定的任意文件；若使用该兼容参数，必须同时 --voice-character，且文件必须是该角色已登记的音色。一般不需要传该参数，自动查库即可。

## 模式和多人限制

当前接口合同中 ref2v 最多携带**一条 reference_audio**：

- 只有一人说话：自动使用他的已登记音色。
- 多人说话：默认选已有音色且本段预计对白时长最多的角色；并列时按首次说话顺序。可用 `--voice-character C01` 指定该段优先人物。
- 请求记录 voiceSelection.selectedCharacterId / unreferenced，明确谁获得了音频约束、谁只带文字音色描述。不得把几个人的声音混成一条参考音频，不能声称一条参考就锁住多人。
- 对多人音色都要求严格一致时，在分镜阶段按说话人拆成短段，再分别带各自音色；保留已批准剧情和空间衔接，修改后重新确认相关步骤。

当前流程要求视频实际携带俯视图，fl2v 已在视频提交入口拦截；旧方案须先调整为 ref2v 并重新确认。以下仅解释旧模式能力：fl2v 本版合同只有首帧和尾帧，不附加 reference_audio；保留人物音色文字描述，并在任务里明确 reason=mode_has_no_reference_audio。这种情况下无法承诺模型复现声线，需要实际试听；若一致性优先，可在用户认可的制作方案下改用支持音频参考的模式或独立配音，不能私自添加未支持参数。

若未来更换视频模型，先核实它支持的音频参考字段、数量与角色绑定方式，再改适配器；不要把 Wan3 的字段照搬给别的模型。

## 审核

原生对白模式下，clips 提交前要求所有实际说话角色都已保存并上传音色。音色库及音频内容加入 clips 的版本指纹；修改会使相关确认失效。

逐段播放，与角色原始音色样本对照：音高/质感/口音、说话人归属、台词和口型是否合理，是否存在换人声或多人同声。参考音频是生成约束，不是同声保证；声音不一致时不能仅因请求携带 URL 就判定通过。

## 上传能力由使用者提供

不预设私人上传服务器。兼容上传器可配置 ZV_UPLOAD_URL（multipart file；返回 code=2000/data URL）及可选 ZV_UPLOAD_PKG；也可通过已连接的上传工具上传 voices.json 中登记的实际 WAV，再执行 `python3 {skill}/scripts/voices.py publish {project} C01 --url 实际音频URL`。只有真实上传该文件后才登记 URL。capture 在上传能力缺失或失败时保留本地 WAV 和 local 状态，不必重复截取；完成上传后恢复 publish。
