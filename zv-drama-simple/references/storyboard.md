# 站位、分镜和分镜图

实际生成时遵循 [依赖图输入规范](image-inputs.md)：工具支持图片输入就传相关参考图，逐张说明位置、尺度与方向约束；不能仅列引用 ID。

存在相邻或内外连通场景时，同时执行 [跨场景空间一致性检查](scene-relations.md)，核对位置、角度、相对大小及连接结构。

分镜创作前必读 [知识库接入规范](storyboard-knowledge-guide.md) 和 [AI 短剧分镜 Agent 知识库 V1.0](storyboard-knowledge-v1.md) 的 02–16 章。按其中工作流设计，再按 P0/P1/P2 复核，尽量遵循其建议；字段映射、例外处理及与当前单一 beat 认领约束的衔接以接入规范为准。

先按 [制作范围](production-scope.md) 筛选集数和场次，默认只为 E01 排站位、分镜及分镜图。全剧剧本仍保留，不要求未选集数拥有素材。

## staging：沿用已确认场景俯视图

每个本批地点关联已审核场景图 imageId 和 floorplanId，locations.items 的物件与坐标直接沿用 floorplans.layout.items，不再另推一套布局。详细制图、校验及机位坐标规范见 [场景俯视图](floorplans.md)。

每场列齐剧本角色：present 表示开场是否在场；后来入场、场外说话者为 false。为在场人物指定实际物件 itemId、位置、坐站卧、N/NE/E/SE/S/SW/W/NW 朝向。坐姿物件需 sittable。不要凭空增加群演；extras=0 时明确“无群演”。opening 用一段可直接用于视频的自然语言写开场，并与坐标相符。

审核页将实际场景图、已确认俯视图与人物站位示意并排。用户在聊天提出移动谁，修改 JSON 后重渲染；没有拖动编辑器。开场之后的走位在分镜 startState/endState 里接力，不用每个片段都回到场次开场站位。

## storyboard：段与镜头

- segment 是一次生成任务，有全局唯一 SEGxx、episodeId、sceneId、mode、sound。
- shot 是段内镜头，有 SHxx、beatIds、seconds、景别、机位运镜、动作、构图、framePrompt、assetIds、startState、endState。
- 同一段不跨场。每个节拍按剧本顺序恰好被一个镜头认领；不能漏台词或重复台词。单个过长台词节拍先回剧本拆分并重新确认，不偷偷改分镜里的台词。
- 秒数先满足动作和对白，再形成节奏；单段总秒数为整数，使用 brief.videoGeneration 中按实际能力核实的上限。不能把此本地约束当作服务未来能力证明。
- 镜头之间交接位置、手持物、眼神、运动方向与情绪。连续场景避免人物突然左右互换。前一段结束状态是下一段开始的依据。
- assetIds 明确本镜使用哪些已确认角色/场景/道具图，不把全剧素材全部塞给模型。

视频提示词由脚本从已确认的镜头和原剧本逐字对白拼出，不需要再写一份容易偏离剧本的视频提示词。用户修改台词应回到 script。

## frames：当前生产模式与旧数据

视频必须实际携带俯视图，新分镜默认使用 ref2v 组织；工具若明确支持首尾帧加俯视图，可按其实际参数映射 fl2v，否则调整分镜并重新确认。每张关键帧生图也必须实际传入对应俯视图文件，不能只登记 referenceIds。

ref2v：每个 shot 一张 role=keyframe；预留一张参考图给场景俯视图，关键帧数量不得超过所选工具 maxReferenceImages 减去俯视图名额，按镜头顺序提交。不要因参考图数量限制悄悄丢镜头，超限就先拆段。keyframe 是对应镜头的起始构图，不是动作的全部过程。

fl2v：每段一张 first_frame（关联第一个镜头），一张 last_frame（关联最后一个镜头）。尾帧是动作完成后的状态，不是最后镜头的开场图。中间镜头靠提示词表达；需要精准中间切点时拆成更短的独立段，后期剪切。

生成时把镜头需要的实际 asset 图送给图像工具，并写清每张参考图的作用。每张图保存 prompt、referenceIds、独立路径；referenceIds 包含本镜使用的俯视图。同一段首尾图可以引用同一组人物/场景，但不能默认用同一文件冒充两个不同状态。



每镜 spatial 必填 floorplanId、cameraPath、visibleItemIds 和 backgroundChange；HTML 展示俯视布局上的机位路线。程序检查路径穿障碍、越界及未知区域，图片直接交用户确认，实际视频背景合理性在视频审片时核对。

图片生成后直接展示 HTML 并等待用户确认，不执行 Agent 图片审核或自动重做。

## 每小段说明生成方式与理由

每个 segment 必须有 mode 和 modeReason。可选择 `ref2v` 或 `fl2v`（首尾帧），不是全剧只能用一种；根据动作、构图控制与实际工具能力选择，在分镜方案审核时让用户看到并确认。modeReason 用一两句说明本段的具体原因，不机械重复“效果更好”。

- **ref2v**：适合需要多张构图参考、多个镜头切换或关键画面约束的段落。HTML 显示“需生成分镜帧 N 张”，N 直接取本段 shots 数，每镜一张，随方案变化自动更新，不另存容易失真的计数字段。已确认俯视图额外携带，不算新生成的分镜帧，但计入工具图片输入上限。
- **首尾帧**：适合起止状态明确、主要是一段连续动作或连续运镜的段落。说明开始/结束状态和选择理由；方案页不显示“需生成分镜帧 N 张”统计。这不代表不生成图片，后续仍制作真实首帧与尾帧供用户确认，并携带俯视图。
- 首尾帧不能假定精确控制段内每个中间切点。若需要精确中间镜头，选择 ref2v 或拆分段落后重新确认。

能力发现时登记 brief.videoGeneration.supportedModes。未登记仅按 ref2v 兼容处理；选择首尾帧前必须确认 supportedModes 含 fl2v，supportsFirstLastWithReference=true，且 maxReferenceImages 至少为 3，证明工具可以同时携带首帧、尾帧及俯视图。若当前工具不支持，继续查找满足要求的工具/技能，或明确提出调整方案，不悄悄省略俯视图。旧项目缺少 modeReason 时先补充真实理由并重新提交方案，不能编造旧确认。
