# 相邻场景的空间一致性

实际生成时遵循 [依赖图输入规范](image-inputs.md)：工具支持图片输入就传相关参考图，逐张说明位置、尺度与方向约束；不能仅列引用 ID。

制作新场景图前，先检查剧本和 `source/novel.md`：它与哪个已生成场景存在物理邻近、门洞连通、走廊连接、内外对应、楼层上下或窗口可见关系？把真实关系登记在 art.sceneRelations。不能因地点名字相似就推断相邻；无法确定的方向、尺度和连接方式明确为 unknown，需补齐关键依据，不能猜成已通过。即使新场景属于不同 entityId，也要实际打开相邻场景图逐项比较。

## 关系数据

art.schema.json 支持顶层 sceneRelations 数组。每条以唯一关系 ID 连接两个不同的 Sxx，关系仅登记一次，检查自动双向执行；所有方向描述以 fromSceneId → toSceneId 为基准。已有项目可暂缺该字段以兼容，但缺失不代表已经检查过无邻接关系。新项目应在第 4 步排查并写出 sceneRelations，确实没有则为空数组。

```json
{
  "id": "R01",
  "fromSceneId": "S01",
  "toSceneId": "S02",
  "connection": "客厅北墙门洞连接走廊南侧入口，属于同一扇门",
  "relativePosition": "走廊位于客厅北侧，同一楼层；入口处无高差",
  "orientation": "从客厅向北出门进入走廊；反向看客厅时朝南",
  "relativeScale": "两侧门洞宽高一致；以同一角色身高和门框作为共同尺度参照",
  "basis": "approved_design",
  "evidence": "用户已确认的布局设计；非原文明确方向",
  "unknowns": []
}
```

basis 为 source / approved_design / unknown。source 的 evidence 指向规范 MD 的具体内容；approved_design 仅用于已确认的补充布局，未确认不能冒用；unknown 必须列出 unknowns。禁止为了生图顺手把推测记录成原文或已批准。同一对地点可以有多个真实连接，分别使用关系 ID，例如门与窗；检查是否互相矛盾，不重复写成两套相反方向的关系。

## 四类关键验收

每张候选对每个已登记相邻地点的已有状态图分别检查：

- **position 物理位置**：相邻方向、上下楼层、地面高差、连接点与通路一致；不能同一时刻从门出去却到另一边，或形成空间重叠、穿墙通路。多场景链条还要回查整体连通关系，避免 A→B→C 与直接 A→C 的设定矛盾。
- **angle 朝向和视角**：对齐场景坐标、相机朝向、门窗的内外侧与可见背景；反向观察会改变画面左右，不能直接以像素位置判错。机位改变、镜头焦距和透视差异不等于物理方位变化。
- **scale 相对尺度**：用共同门框、人物、窗户、台阶或已确认尺寸比较比例；门洞两侧尺寸、层高、通道宽度及可容纳的人物合理一致。不直接比较两张图中的像素大小；透视严重或缺少尺度参照时记 uncertain，不编造精确米数。
- **connection 连接结构**：门窗轮廓、门框、台阶、共享墙体、开口及跨边界可见物件保持同一结构；正反面饰面可以不同，开合/昼夜/损坏等变化必须有明确状态依据。不能新场景无依据多出一扇通往旧场景的门。

qc.criteria 的 id 使用 `adj_<关系ID>_<对照图片ID>_<类别>`，例如 `adj_R01_A03_scale`，四类均为 critical。requirement 明确关系与应保持的事实，attempts[].checks 的 observation 写实际看到了什么、如何对齐视角、哪些差异合理、哪里冲突或无法判断。重要未知、遮挡或图内缺少证据时记 uncertain，可结合经确认的场景图与俯视图澄清，不填笼统“符合”。

场景生图 assets 在同阶段已有相邻场景图中查找对照；俯视图 floorplans 同时对照相邻场景图和已有俯视图。模型还需对照当前场景本身的俯视布局。脚本绑定关系全文、对照图 ID/状态/提示词/文件哈希，不递归绑定相互的 qc，以避免循环依赖。追加新相邻图后，旧图的相关检查也须补齐，保留原候选及重做计数。修改关系须重新确认美术设定及受影响下游。

生成参考：assets.referenceIds 可以引用 assets 数组中更早的已登记相邻场景图；同组人物/道具约束不放松。提示词要说明这是邻接几何参考，不是要把两个地点混成同一房间。通过实际参考图固定公共门窗、方向与尺度。先保留已确认旧场景作为基线修正新图；如果旧场景本身有问题，应明确指出并走修订确认流程，不能偷偷改旧图迁就新图。

跨制作范围的地点不因邻近就擅自生成：有已存在且可核对的图片则登记来源用于检查；若图片还不在本项目，先在授权范围内归档并说明用途，不绕过当前范围校验添加正式交付素材。没有可用旧图时仅能做关系设定检查，不宣称完成逐图对照。镜头需要出范围外背景时先调整并确认制作范围/剧本登记，再制作所需素材。

## 展示与后续

第 4 步展示场景关系；场景图、俯视图及素材状态库提供“相邻场景关系与对照图”，用户可展开查看关系、尺度、依据和旧图。各候选的四类检查沿用原 QC 展示。无关场景不要求互相一致，不把所有场景混为一个组。

冲突或不确定沿用首次生成加最多 3 次重做；耗尽后取最合适候选并展示未解决项，不称为无冲突。进入站位、分镜与视频时仍对照关系：跨门、出入画、窗口外景和运镜露出的背景应成立，跨场段之间的移动方向与尺度也要衔接。脚本只检查关系引用、检查项完整及版本失效；视觉空间判断由模型实际看图完成，不声称自动重建三维场景。
