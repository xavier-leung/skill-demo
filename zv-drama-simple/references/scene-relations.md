# 相邻场景的空间一致性

实际生成时遵循 [依赖图输入规范](image-inputs.md)：工具支持图片输入就传相关参考图，逐张说明位置、尺度与方向约束；不能仅列引用 ID。

制作新场景图前，先检查剧本和 `source/novel.md`：它与哪个已生成场景存在物理邻近、门洞连通、走廊连接、内外对应、楼层上下或窗口可见关系？把真实关系登记在 art.sceneRelations。不能因地点名字相似就推断相邻；无法确定的方向、尺度和连接方式明确为 unknown，需补齐关键依据，不能猜成已知。即使新场景属于不同 entityId，使用相关场景图作为生成参考。

## 关系数据

art.schema.json 支持顶层 sceneRelations 数组。每条以唯一关系 ID 连接两个不同的 Sxx，关系仅登记一次，关系可双向查找；所有方向描述以 fromSceneId → toSceneId 为基准。已有项目可暂缺该字段以兼容，但缺失不代表已经检查过无邻接关系。新项目应在第 4 步排查并写出 sceneRelations，确实没有则为空数组。

```json
{
  "id": "R01",
  "fromSceneId": "S01",
  "toSceneId": "S02",
  "connection": "客厅北墙门洞连接走廊南侧入口，属于同一扇门",
  "relativePosition": "走廊位于客厅北侧，同一楼层；入口处无高差",
  "orientation": "从客厅向北出门进入走廊；反向看客厅时朝南",
  "relativeScale": "两侧门洞宽高一致；以同一角色身高和门框作为共同尺度参照",
  "basis": "approved_design",
  "evidence": "用户已确认的布局设计；非原文明确方向",
  "unknowns": []
}
```

basis 为 source / approved_design / unknown。source 的 evidence 指向规范 MD 的具体内容；approved_design 仅用于已确认的补充布局，未确认不能冒用；unknown 必须列出 unknowns。禁止为了生图顺手把推测记录成原文或已批准。同一对地点可以有多个真实连接，分别使用关系 ID，例如门与窗；检查是否互相矛盾，不重复写成两套相反方向的关系。

## 生成参考与展示

将相邻场景的物理位置、方向、尺度和连接结构写入生成提示词，实际传入相关已有场景图；这是生成约束，不是生成后的图片审核。assets.referenceIds 可引用数组中更早的已登记相邻场景图，不能跨人物或道具混用身份。

跨制作范围的地点不因邻近就擅自生成。缺少来源图时如实说明，并在授权范围内补充必要输入；不能凭空声称已有参考图。

第 4 步展示场景关系；场景图、俯视图和素材状态库展示相邻关系与参考图片，供用户查看。取消 position/angle/scale/connection 的图片验收项、逐候选观察、评分和自动重做。脚本仍验证关系 ID、引用地点及未知依据，不声称已判定视觉空间正确。

分镜设计继续遵守已确认空间关系；视频生成后的背景与运动连续性审片保留。
