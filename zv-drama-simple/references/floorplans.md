# 场景俯视图与镜头空间连续性

实际生成时遵循 [依赖图输入规范](image-inputs.md)：工具支持图片输入就传相关参考图，逐张说明位置、尺度与方向约束；不能仅列引用 ID。

存在相邻或内外连通场景时，按 [跨场景空间关系](scene-relations.md) 准备位置、角度、相对大小及连接结构的生成约束。

## 顺序与用途

俯视图归入第 7 步 assets：**每个新场景的首张场景图生成完成 → 立即制作该场景唯一俯视图 → 场景状态图与俯视图在第 7 步一起展示确认 → 第 8 步站位**。不等待全部场景生成完成，不另设 floorplans 确认步骤；整体十二步。floorplans.json 仍独立保存数据，但由 assets 的校验、版本指纹和确认记录共同管理。

俯视图是一张真实独立的场景参考图片，表达从上方看室内的设计布局，不是审核页自动绘制的站位 SVG，也不是另行装修设计。它要忠实解释已生成场景图中的墙、门、窗、家具、通道和位置关系。室外场景同样制作场地俯视布局图，不凭空增加室内墙体。

每个本批实际使用的场景一个 FPxx，写入 floorplans.json 的 images。全局 ID 不能与角色/场景素材重复。entityId 是 Sxx，view 固定 overhead，referenceIds 指向同一场景的已生成参考图。同一个 Sxx 只能有一个俯视图。昼夜、光照、天气、道具状态等后续状态直接复用，禁止按状态重复生俯视图；新增状态在生成提示词与参考输入中沿用已有俯视图，不触发图片复检或自动重做。真正改变建筑空间布局时先修订设定并重新确认，或明确登记为新的场景 ID，不给同一场景叠加第二张布局。


## 制图

1. 实际查看场景图，识别可见的墙体走向、门窗、主要家具、物件相对位置与通行空间。
2. 建立统一坐标：原点左上，x 向右、y 向下，范围 0..1。上北下南只是项目约定，不宣称真实地理朝向；orientation 写清约定，所有图和镜头共用。
3. 将物件写成 layout.items：id/name/kind、x/y/width/height、sittable、blocksCamera、basis、evidence。kind 可为 wall/door/window/furniture/passage/anchor。坐标为俯视平面，不能抄透视图像素框。
4. basis=observed 表示场景参考图有依据，evidence 描述看到的依据。看不见、无法推断的区域写 unknownZones；推测物件 basis=inferred，不作为可确定入镜背景。不可擅自补一扇门让运镜更方便。
5. 将实际场景图和这份布局交给图像生成工具，制作干净、正交、无透视的俯视图：家具轮廓和标识清楚，门窗朝向正确，通道留白，必要时标 FPxx/物件编号。不要画人物，不画电影画面装饰；未知区域做明确标识。
6. 保存独立图片，例如 images/floorplans/S01-overhead-v001.png。图像布局与 layout 数据必须一致，不能一边移动图上的桌子一边保留旧坐标。

俯视图尺寸和家具距离是供镜头规划使用的估计，不能当作工程测量或施工图。物件坐标精度不足以证明真实 3D 可通行；图片由用户确认，实际运动效果在视频审片时核对。

## 展示确认

俯视图生成后与来源场景图、layout 数据一起在第 7 步展示，由用户确认；不进行 Agent 图片专项验收、逐候选比较或自动重做。保持每场景一个 FPxx、引用同场景来源图、图片文件真实存在、layout 坐标有效等基础约束。

```bash
python3 {skill}/scripts/workflow.py submit {project} assets
```

用户要求改布局时再修订第 7 步数据及图片，并重新展示确认；俯视图变化仍使相关下游步骤失效。

## 站位及运镜如何使用

staging.locations 增加 floorplanId。imageId 必须是该俯视图的来源场景图；items 直接投影复制 layout.items 的 id/name/x/y/width/height/sittable，不再独立推算一套坐标。用户改空间布局回第 7 步 assets 中的 floorplans 数据，人物位置变化才改 staging。

storyboard 的每个 shot 增加 spatial：

```json
{
  "floorplanId":"FP01",
  "cameraPath":[
    {"x":0.3,"y":0.8,"lookAtX":0.5,"lookAtY":0.3},
    {"x":0.5,"y":0.8,"lookAtX":0.5,"lookAtY":0.3}
  ],
  "visibleItemIds":["I01","I02"],
  "backgroundChange":"机位由西向东平移；门逐渐移向画面左侧，圆桌从右侧进入前景。"
}
```

固定镜头也记录一个机位和注视点。曲线运动用多个点近似；不要只写起终点却让中间直线穿桌。每段保持同一场景布局；不同镜头切换可以改变机位，连续运动应承接前段结束位置。

程序核对机位/注视点在 0..1 内、引用同场景的同一俯视图、背景物件来自该布局；检查整条折线路径是否进入障碍或 unknownZones。不能将 inferred 物件列为确定的 visibleItemIds。它不模拟完整 3D、镜头视锥、摄影设备体积或家具高度；遮挡、透视与背景进入退出仍需模型按图检查，并在 backgroundChange 中写清。

镜头的 assetIds 必须包含 FPxx，分镜图 referenceIds 同步包含它。生成每张分镜关键帧/首尾帧时，必须把对应俯视图文件实际传入生图工具，不能只在 referenceIds 列出它。工具不支持则换用已授权且支持图片输入的工具；没有可用工具时说明阻塞。出分镜图时明确俯视图只提供空间约束，输出仍为该镜头的正常视角，不能把平面图画进镜头。

## 视频工具与成片核对

ref2v：每段参考图中加入一张已确认俯视图，明确标注“仅用于空间关系，不是视频画面或切镜”。参考图总数遵循已发现工具的 maxReferenceImages，给俯视图预留一张；超出先拆段，不默默丢弃俯视图。

fl2v 是否可用取决于所选工具能否同时接收首尾帧和俯视图；不支持则使用参考图方式或调整分镜并重新确认，不静默省略俯视图。旧 Wan3 适配器依旧不支持此组合。

视频提示词同时写入空间约束：墙门窗家具不得漂移、镜像、凭空增加；机位自然移动，背景按视角发生合理显露/遮挡；未知区域不得擅自补全。

生成后逐段看片，重点抽查运动开始、途中、结束：门是否换墙，家具是否滑动/消失，空间是否变宽变窄，反打是否左右颠倒，机位是否穿物。俯视图能加强约束与验收依据，不能保证生成模型严格遵循几何；发现问题仍需修正，不将“传了俯视图”当成空间合格证明。
