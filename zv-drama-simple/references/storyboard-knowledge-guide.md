# 分镜知识库接入规范

本技能内置用户提供的 [AI 短剧分镜 Agent 知识库 V1.0 全文](storyboard-knowledge-v1.md)。首次进入 storyboard 步骤，先读本规范，再读全文的 02–16 章；恢复或修改时按规则编号回读相关章节。17–18 章为来源索引，需要追溯时再查。剧本阶段参考 WF-01/02，站位阶段参考 WF-03，分镜图与视频复检沿用相关 P0/P1/P2 规则。

## 适用原则

- 尽量遵循知识库的视听语言、连续性、剪辑和节奏建议；用户明确要求、已批准的改编范围及剧情优先。知识库不是新的剧情来源，小说事实仍只能查 `source/novel.md`，对白以已确认 script 为准。
- 保留本技能十三步、现有 JSON schema、固定 HTML 展示及聊天确认流程。全文里的 YAML、字段名、场景案例、回归测试和增量接入建议是参考，不直接作为项目数据或本次额外任务执行。
- P0 是关键错误检查，先修复或明确待确认；不能以节奏/风格为由掩盖遗漏事实、台词错人、因果断裂或不可能的物理状态。若已确认的剧本本身需改，回到对应步骤修订并重新确认，不在分镜偷改。
- P1 优先修复；有意越轴、跳切或非线性叙事可以保留，但须说明目的、观众可见的方向/时间线索及复核依据。P2 按剧情取舍，不强求固定镜数、特写比例或运镜次数。
- 文中的 2.31 秒是样本观察，30 度是实践提示，均不是硬阈值。片长、镜头秒数和参考素材上限仍遵循 brief 与实际服务合同。

## 生成与复核两轮

1. **事实与节拍**：由已确认 script 的 beat ID 回查 `source/novel.md` 和已批准改编；明确触发、行动、结果、观众新增认知及关键揭示时机。区分原文事实、补充调度和未知，不提前泄露应由后续镜头揭示的证据。
2. **空间与状态**：沿用 floorplans、staging 和角色/道具 ID，建立人物目标、动作轴的有序端点、机位侧、视线对象、道具持有者与动作阶段。场景坐标与画面左右分开表述，不能用屏幕方向推翻已确认布局。
3. **预剪辑**：先设计每镜观看任务及切入/切出理由，再选景别与机位。默认考虑固定机位；运镜需有揭示或跟随目的、起止构图和可走路径。对白可留在听者反应上，不机械逐句正反打。
4. **时间与声音**：试读对白，检查读字、动作、反应和停顿所需时间；区分并行声画与串行动作。画外对白保留原说话者，画面听者不误做口型。J/L-cut 只是设计选项，须有当前音轨和剪辑工具能实现的明确方案，不能写了就宣称已实现。
5. **独立复核一遍**：完成初稿后，从原文、剧本、俯视图及相邻镜头记录出发，按 P0 → P1 → P2 查证，不把初稿的自我描述当作正确证据。逐切点检查「保留事实 → 时间关系 → 空间/动作 → 声画覆盖 → 新增贡献」，包括跨 segment 的切点。
6. **修订后回查**：同步检查受影响节拍、前后镜头、状态、声音和总时长，再展示 HTML。在聊天审核说明中列出尚存问题与有意例外，写明规则编号、镜头 ID、依据和取舍；没有问题也只能说明实际检查范围，不能用脚本通过冒充全部电影语言检查通过。

## 映射到现有字段

不要把知识库的 snake_case 字段直接加进严格 schema。将必要创作信息写入以下现有字段，保持简洁、可执行；没有结构化字段的判断在审核聊天说明，不伪造机器验证记录。

| 知识库概念 | 当前承载位置 |
|---|---|
| 原文事实/改编依据 | `source/novel.md` 的章节/段落位置、outline 的 `origin.evidence`；审核说明引用对应 beat/shot ID |
| 场景、节拍、镜头顺序 | `script.episodes[].scenes[].beats[]`；`segments[].sceneId`、`shots[].id/beatIds`；按现有数组顺序，不另加 sequence_index |
| function / information / 切点动机 | `shot.action` 写具体观看任务、动作及关键揭示；`composition` 写需要保留的关系与回接线索；审核说明解释取舍 |
| 景别、构图、角度、运动理由 | `size`、`composition`、`camera`；camera 写机位、运动起止与理由，固定镜头明确固定 |
| 轴线、机位侧、屏幕位置、视线 | `camera` / `composition` 使用稳定角色和物件 ID 表述；不以“左边”代替场景坐标 |
| 动作阶段、持有者、手、姿态、时空省略 | `startState` / `endState`；注明连续承接或时间跳跃依据，相邻镜头核对同一实体 |
| 布局、路线、环境背景变化 | `spatial.floorplanId/cameraPath/visibleItemIds/backgroundChange`，沿用已通过的俯视图 |
| 时长、对白归属、画内外、同步点 | `shot.seconds`、原 script 的 `speaker/text/delivery`、`segment.sound`；sound 用 shot/beat ID 和段内秒数说明声画关系 |
| 生成任务和素材 | segment 是生成单元，shot 是镜头；`assetIds`、frames 的镜头引用、Wan3 任务和 clips 记录承接，不能把镜头数直接当请求数 |

本技能每个 beat 只允许一个镜头认领。知识库允许一次动作跨镜时：跨镜延续状态，但不重复认领 beat；确需把同一节拍拆给多个镜头时，先回 script 拆分并重新确认。对白跨切点若现有字段/生成模式不能准确表达，调整分段或经确认拆节拍，不绕过顺序与覆盖校验。

## 复核检索表

按适用条件检查，不适用项不硬套；具体执行、失败示例与修复方式读全文对应编号。

| 级别 | 逐项检查 |
|---|---|
| P0-01–04 | 关键事实与对白覆盖；人物场景资产一致；连续动作阶段；道具持有与状态 |
| P0-05–08 | 因果与人物所知；实际位置和通路；台词说话者；动作时长与生成约束 |
| P1-01–04 | 动作轴及重建；视线对象；运动方向/出入画；意外跳切 |
| P1-05–08 | 姿态朝向；必要空间交代；声画时序；理解下一镜的线索 |
| P2-01–04 | 每镜贡献；无效重复；景别匹配叙事；运镜动机 |
| P2-05–08 | 避免逐句正反打；省略可推断日常过程；反转识别时间；景别是否遮蔽信息 |

图像生成后结合逐图 QC 检查身份、姿态、轴侧、视线、手持物与布局；保持既定最多三次重做规则，best_available 的残留问题不得写成 P0 已解决。视频生成后实际观看、试听相邻片段，复核动作衔接、说话人、口型、音色、背景、声画同步及可读时长；文本方案正确不代表生成结果正确。自动校验器只负责已有的结构、引用、时长和空间约束，以上电影语言判断仍由模型实际检查。
