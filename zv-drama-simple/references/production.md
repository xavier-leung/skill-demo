# 视频生成与后期

## 先发现能力，不指定模型或服务

在制作要求阶段先发现一次，进入分镜前和真正提交前再核实能力可用性：

1. 查看本会话可用工具，按工具名/描述搜索视频生成、图生视频、video generation 等能力。已有连接器能完成任务时优先使用，读取真实参数与使用要求。
2. 同时检查可用技能目录里的视频生成技能，读取适用技能的 SKILL.md，按其指示确认底层工具、命令、连接和认证确实可用。技能存在不等于具备执行能力；不要仅凭名字或历史记忆选择服务。
3. 用户已经选择了当前可用且满足要求的工具就沿用，否则根据参考图输入、俯视图、时长、画幅、音频与音色参考支持选择合适能力。不默认指定供应商、模型、接口、分辨率或付费额度；旧服务授权不能自动迁移到新服务，依实际授权执行。
4. 必须能实际传入关键帧和场景俯视图；不能用仅文本生视频替代。确认图片数量、时长是否可为小数、音频和参考声音数量等真实限制。将工具/技能出处和限制记录进 brief.videoGeneration，供分镜预算与请求组装使用。
5. 找不到可执行且满足要求的能力时，明确提示：“需要视频生成能力：请连接可用的视频生成工具或安装并配置相应技能，需支持关键帧和场景俯视图输入。”说明已检查哪些能力及缺项、接入后将继续哪个步骤。不要自动回退 Wan3、编造视频、把提交计划当结果，或擅自安装、开通/购买服务。仍可完成不依赖缺失能力的已授权前置工作，分镜时长/素材约束未知时不伪造其确认。

这是制作流程的能力发现，不是在修改技能时替用户执行生成。参考技能仅提供媒体能力，不调用原小说制作技能替代本技能创作步骤。

## 通用配置

新项目使用 brief.videoGeneration，不创建 brief.wan3。尚未找到能力可写：

```json
{"status":"unavailable","reason":"尚未找到可执行且支持俯视图参考的视频工具"}
```

发现后设 status=ready，必须填 provider、tool（实际工具名或技能路径）、evidence（能力核实出处）、maxSegmentSeconds、maxReferenceImages、maxReferenceAudio、integerSeconds、audio；model、resolution 仅在工具需要且已核实后填写。supportedModes 登记实际支持的 ref2v/fl2v；首尾帧同时传俯视图需 supportsFirstLastWithReference=true 且图片上限至少为 3。数值以当前工具为准，不照抄旧 Wan3 限制。maxReferenceImages 至少为 2，以容纳关键帧和俯视图。tool/source 不存密钥。

配置变更按正常 brief 修订重新确认，不悄悄更换已批准的生产方式。ref2v / fl2v 是本技能的帧组织标签，不是所有工具都接受的 API 参数；实际映射以所选工具为准，始终保留俯视图输入。默认用 ref2v 组织逐镜关键帧；首尾帧加俯视图仅在工具明确支持时使用，不能混入不支持的参数。

## 准备、实际执行和收集

```bash
python3 {skill}/scripts/video_generation.py prepare {project} SEG01
python3 {skill}/scripts/video_generation.py start {project} GEN-SEG01-实际指纹
# 此处由 Agent 调用实际发现的工具/技能，不是脚本自动发送请求。
# 按 job.media 的真实文件/URL传图，保留空间约束、原台词和角色音色关联。
python3 {skill}/scripts/video_generation.py collect {project} GEN-SEG01-实际指纹 --file videos/实际结果.mp4 --task-id 实际返回的任务或结果ID
```

prepare 输出独立任务、图像/音色依赖、已确认镜头/对白和能力信息，脚本自身不产生视频。start 在实际工具调用前记录启动状态并核对指纹，防止同一任务重复付费；工具执行、查询、下载按其文档完成，持续处理直到得到真实文件。记录真实提交参数、输入图顺序及任务 ID，不记录凭据。发送超时或结果未知时先用真实任务 ID 查询/恢复，不盲目重发；必要时记录不确定状态并说明阻塞。失败后的新尝试需保留原任务和原因，不能删除任务来绕过保护。

collect 用 ffprobe 检查实际文件，保存下载凭据和 qc=false 的片段草稿，可继续使用 voices.py capture 从已收集视频提取首个声音。它不替代工具调用、视频审片或用户确认。工具原生支持直接返回文件时仍记录真实结果 ID，不伪造 taskId。

发送前再次核对俯视图确实在工具图片输入中；数量上限依据能力配置拆段。音色由 voices.json 维护，支持时携带所选角色音频。本版通用准备器每段最多选择一个角色声音；支持多声音的工具也不能在没有明确角色映射时随意混合。更强的能力可经核实扩展映射，不能假称已经支持。

旧 brief.wan3 项目保留兼容读取，仅在用户继续原方案时按 [旧适配器](legacy-wan3.md) 执行；新项目不会自动选择它。

分镜与生成后复检遵循 [知识库](storyboard-knowledge-guide.md)、[场景俯视图](floorplans.md) 和 [角色音色](voices.md)。

## clips 审核

下载后逐段播放；发现该角色首个说话分段已完成时，先按 [角色音色库](voices.md) 为这些角色截取、试听并上传首段独立语音，再继续生成其后续对白。必要时提取开头、中间、结尾以及动作变化处的帧辅助查看；抽帧不能替代听声音。检查：

- 人物身份、服装、人数、肢体、手持物和空间位置；对照俯视图检查运镜中墙门窗家具是否漂移、镜像、凭空增减或被镜头穿过。
- 实际动作是否实现镜头意图，镜头衔接是否可剪。
- 每句对白是否完整、说话者是否正确、口型/音色是否可接受。
- 真实时长、画幅、视频/音轨是否正常。

检查并修复后，把选定的片段条目汇总成 clips.json。每段只选一个正式版本；写实际秒数、真实 taskId 和 qc.notes。clips 的 HTML 展示本地视频，用户确认后再合成。

## 声音、对齐与字幕

brief.audioMode=native：使用所选工具实际生成的原生音轨，首次说话的实际声音作为角色基准，截取、上传并绑定角色。后续支持 reference_audio 时自动使用同一 URL；不支持或多人超出上限时明确限制，不能承诺跨段一致，效果仍需听。

brief.audioMode=external：使用已可用的 TTS/录音工具制作逐句或整集对白，保存在 audio；保持 script 原句和说话者 ID。nativeGain 通常设 0，外部对白 audioTracks.role=dialogue。若用户需要严格口型匹配，还需要实际具备口型修正能力的工具，不能声称混音会自动修好口型。

字幕时间以**最终剪辑后的实际声音**为准，不直接照抄分镜估时。可逐句试听定位，或使用用户已选的 HypiHub WhisperX 转写/对齐；转写结果与剧本逐句比对，生成漏词不能通过改字幕掩盖。

语音转写/对齐是可选外部能力：从当前工具或技能中发现并按其文档配置，使用当前用户的项目、运行配置和凭据。没有可用对齐工具时，可实际试听完成字幕，不沿用作者电脑路径、账户或服务授权。

## edit 准备与合成

edit.episodes 每集字段：

- cuts：按 storyboard 顺序列 clipId、in、out（秒）。本版支持每段裁入/裁出与顺序拼接，不包含转场编辑器；大幅重排回分镜重新确认。
- nativeGain：原生音量倍率。
- audioTracks：本地 file、gain、offset 秒、role。音乐/环境声按需加入；未请求时不自动找付费音乐。
- captions：start/end 秒、text、可选 speaker；按时间排序。
- subtitleMode：none / soft（MP4 可选字幕轨）/ burn（烧录，FFmpeg 需支持 subtitles/libass；先确认中文字体可用）。
- file：新版本成片路径，例如 videos/E01-final-v001.mp4。
- qc：准备合成时 false，实际看片后 true。

```bash
python3 {skill}/scripts/assemble.py {project} --episode E01
# 合成后实际播放，检查和修正，填写 qc，随后提交审核。
python3 {skill}/scripts/workflow.py submit {project} edit
```

合成脚本统一帧率和画幅，为无声片段补静音轨，混合额外音轨，按字幕模式封装成片，输出 `<成片名>.render.json` 记录剪辑/混音/字幕规格及输入输出哈希。提交 edit 时核对记录；修改字幕或音轨后必须重新合成，不能把旧视频配上新 JSON 就送审。已有成片不覆盖；新版本换 file 路径。字幕同时保留独立 SRT。

移动成片时应连同 `.render.json` 保留；通过 assemble 产出才有可核对的合成记录。soft 字幕在不同播放器中的默认显示方式可能不同，通用分享成片优先 burn，并实际确认中文字体和安全边距。

最终播放核对整集剧情、字幕可读性、声音大小、结尾截断和片段连续性。最后向用户提供成片与 edit 审核页，并等待最终确认。不要因 ffprobe 成功就宣称对白、画质或字幕正确。
