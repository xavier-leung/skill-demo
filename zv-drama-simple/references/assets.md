# 人物与美术、图像制作

实际生成时遵循 [依赖图输入规范](image-inputs.md)：工具支持图片输入就传相关参考图，逐张说明位置、尺度与方向约束；不能仅列引用 ID。

存在相邻或内外连通场景时，同时执行 [跨场景空间关系](scene-relations.md)，核对位置、角度、相对大小及连接结构。

同一实体的多状态图按 [状态图分组](asset-groups.md) 组织，生成提示词明确保持项与允许变化。

第 6 步起先按 [制作范围](production-scope.md) 获取所选剧本需要的实体，默认 E01；下文“角色”和“本批地点/道具”均仅指所选范围，不要求为全剧文字设定中的所有角色生图。

## characters 与 art：先定文字，再出图

characters 使用 outline 的同一批 Cxx，不重新增删角色。appearance 写可画的年龄感、体型、发型、面部识别点；costume 写服装轮廓、主色、面料和必要配饰。personality、speechStyle、voiceDirection 分开写，后者只是音色方向，不代表已取得固定声音 ID。imagePrompt 包含全局画风、人物外貌和服装，避免混入情节动作。

art 使用 outline 的 Sxx/Pxx。每景 layout 写入口、主活动区、主要物件的空间关系；anchors 写可看见的稳定标志；lighting 只列剧情实际用到的状态；imagePrompt 明确无人空景，不把角色与背景烘焙成同一张设定图。道具写用途相关的尺寸参照、材料、状态变化，白底无手。普通装饰物归场景锚点，不把每把椅子都独立建道具。

## anchors：定妆先由用户确认

1. 使用当前可用的真实图像生成工具；在 brief 登记所用能力，遵守宿主工具规定。
2. 每人先生成一张 `view: character-sheet` 横向整版角色设定图，严格按 [角色设定图版式](character-sheet.md)：左侧正面半身大图，右上正/侧/背全身三视图，右下服装、双手、鞋子细节；不生成头顶/头发局部图；仅左侧正面大头照清晰，其他视图的头部均打马赛克。旧 front-full 仅兼容历史数据，新图不采用旧单视图默认。
3. 文件建议 `images/characters/C01/anchor-v001.png`。anchors.images 的 entityId 对应 C01，referenceIds 为空，prompt 保存实际提示词。
4. 保存真实图片并完成文件、格式、引用等基础校验；不执行 Agent 看图验收或自动重做。
5. submit anchors，展示并等待用户确认；确认前不要批量派生。

## assets：派生参考图与真实场景

新角色设定整图已经包含正面半身、三视图和服装/手/鞋细节，不再强制重复生成一张正脸近照；按实际镜头需要追加独立 portrait 或其他状态。旧 front-full 项目仍需正脸近照。每张角色图必须 referenceIds 引用**同角色已确认锚点**；不要用新文生图重新猜长相。姿态不同不等于可以变脸、变衣服。资产 ID（Axx）全局唯一，不能与 anchors 重复。

场景按本批实际出现地点出图，entityId=Sxx，view 可写 `empty-room-night` 等明确用途；光照/服装状态需要多个版本时同 entityId 使用不同素材 ID。取景要能读出站位所依赖的物件；图中没有的桌子、楼梯不能沿用文字设定假设它存在。道具 entityId=Pxx，状态在 view 中写清。

图像路径全部位于项目目录。工具输出在外部临时目录时复制到项目里再登记，保留原始分辨率，不只保存远程 URL。HTML 读相对路径；图像工具本身不支持本地文件时才按实际需要上传。

只有真实生成并保存的图片才进入展示；测试 SVG 不能冒充正式视频素材。图片无需 qc，用户确认另存在 workflow.json。

第 7 步中，每个新场景首图生成后立即制作该场景唯一的 [俯视图](floorplans.md)，与场景图一起展示确认。后续状态复用，不重复生成俯视图，也不开展 Agent 专项验收。用户要求修改时再修订并重新提交。

voiceDirection 只提供第一次生成声音的方向；实际声线须在首个说话视频生成后按 [角色音色库](voices.md) 截取、保存、上传并绑定角色，不能仅靠文字描述维持声音。
